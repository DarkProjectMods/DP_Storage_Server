# DP_Storage_Server

Серверный graft-мод DayZ: живые операции с persistence-слоем (`storage_1`) без
остановки сервера — чтение и хирургический вайп персонажей в `players.db`,
далее вайпы слоёв мира и SQL-зеркало.

Работает поверх [KR_GRAFTED](https://github.com/KRdayzmodding/KR_GRAFTED) —
C++-плагин (`DP_Storage.grafted.dll`) вызывается из Enforce-скриптов как обычные
нативные функции. Без ядра GRAFT мод компилируется пустым (`#ifdef`) и ничему
не мешает.

## Возможности (v1)

| Функция (натив 3_Game) | Что делает |
|---|---|
| `StorageApiVersion()` | версия плагина и SQLite (self-test) |
| `StoragePlayersReport(path)` | отчёт по players.db: версия схемы + список оффлайн-игроков |
| `StorageWipeOfflinePlayer(path, uid)` | вайп одного персонажа (работает и для оффлайн, и для онлайн — см. ниже) |
| `StorageWipeAllPlayers(path)` | вайп ВСЕХ персонажей разом |
| `StorageUpsertPlayerName(uid, name)` | ник игрока в зеркало (при коннекте) |
| `StorageDumpBegin/Entity/End(layer…)` | осмотр слоя: сущности в `entities_dump` зеркала |

**Кик онлайн-игроков при вайпе**: после вайпа (одиночного или всех) плагин пишет
флаг `DP_Storage_kick.txt`, сервер в течение ~5 с кикает вайпнутых через
`DisconnectPlayer` — следующий вход = свежий персонаж.

**Вайп слоёв мира** — два режима:

- *при следующем старте* (любой слой): флаг обрабатывает плагин в `GRAFT_ON_LOAD`
  (до чтения persistence движком), удаляя файлы слоя из `storage_1/data/`;
- *живьём, без рестарта* (`vehicles`, `zombies`, `animals`, `loot`, `stashes`,
  `buildings`, `events` — краши `CrashBase` и заражённые зоны `EffectArea`):
  решёточный обход карты сферами `GetObjectsAtPosition`, сущности класса слоя
  удаляются из мира партиями (25 клеток/тик, до 400 удалений/тик — без фриза).
  Игроки не трогаются никогда; `loot` — весь лежащий в мире лут (корень иерархии —
  сам предмет), включая контейнеры: CE сама спавнит и **набивает их содержимым**
  (флаг `<hoarder/>` в cfgspawnabletypes: палатки, бочки, SeaChest, боксы),
  поэтому «есть содержимое» не признак игрока. `stashes` — только то, что CE не
  спавнит вообще (nominal 0): зарытое `UndergroundStash` и `WoodenCrate`.
  `doors`/`types`/`events` живьём невозможны (не сущности: анимации зданий и
  бухгалтерия CE) — только при рестарте.
  Проверено на проде: 262 зомби/животных за 60 c; 23 548 предметов лута за 59 c;
  события: 16 заражённых зон + 6 вертолётов.

**SQL-зеркало** `profiles\dp_storage_mirror.db` (SQLite, WAL): каждые 30 с —
снапшот `players` (uid, alive, data_len), `layer_files` (файлы/размеры data/),
`mirror_meta` и `player_names` (ники — пишутся при коннекте игрока). Для чтения
людьми и внешними инструментами — готовые представления:

- `v_players` — игроки: **uid + ник**, alive, размер персонажа, обновлено;
- `v_layer_summary` — слои агрегированно: layer, files, bytes, updated.

Просмотр: любой SQLite-клиент, например [DB Browser for SQLite](https://sqlitebrowser.org/)
(портативный zip, без установки). Нюанс WAL: при копировании базы брать и `-wal`
файл рядом; при обычном открытии клиент видит свежие записи сам.

**Управление из DB-клиента** — таблица `storage_commands` в зеркале: вставляете
команду строкой, плагин подхватывает за ~5 c и пишет статус/результат обратно:

```sql
INSERT INTO storage_commands(cmd, params) VALUES('dump','vehicles CivilianSedan*');
INSERT INTO storage_commands(cmd, params) VALUES('live_wipe','loot Ammo_*');
INSERT INTO storage_commands(cmd, params) VALUES('wipe_player','pP0a...');   -- + кик, если онлайн
INSERT INTO storage_commands(cmd, params) VALUES('wipe_all_players','');     -- все + кик всех онлайн
INSERT INTO storage_commands(cmd, params) VALUES('boot_wipe','vehicles');    -- на следующем рестарте
```

- `wipe_player` исполняется сразу, ответ — в колонке `result` (`done`/`error`);
- `live_wipe`/`dump`/`boot_wipe` пишутся в соответствующие флаг-файлы (`dispatched`);
- справка прямо в клиенте: представление `v_help` (список команд и синтаксис).

**Веб-панель** — `web/` (чистый Python stdlib, без зависимостей, только 127.0.0.1):

```
py -3.12 DP_Storage_Server\web\storage_web.py        # → http://127.0.0.1:8790
```

- категории-слои (включая `events`): открытие показывает прошлый дамп сразу и
  запускает свежий (~30–60 c, обход карты), таблица обновляется сама;
  **точные количества без лимитов**;
- **дерево типов**: `Тип · количество` → экземпляры с координатами и здоровьем
  (ленивое раскрытие веток), удаление **одного предмета** (`@ X,Z,1` — радиус 1 м);
- **карта многослойная**: все сдампленные слои одновременно, легенда с чекбоксами
  и цветами по слоям (события — оранжевые), фон `web/map.png` (квадрат на весь
  мир, сейчас — CETool 2048²), зум колесом, пан перетаскиванием, фильтр по типу,
  клик по точке — удаление именно её; недостающие дампы заказываются при открытии.
  Система координат: X — восток, **Z — север**, вертикаль инвертирована
  (`screen_y = 15360 − z`);
- игроки: ники, вайп по одному (с киком онлайн) и кнопка «Вайпнуть ВСЕХ»;
- сводка слоёв (живой вайп / при рестарте) и журнал команд.

**Осмотр слоя и точечное удаление** — спецификации в флаг-файлах (одна на строку):

```
<слой> [тип | тип*] [@ x,z,радиус]
```

- `DP_Storage_dump.txt` — **осмотр**: список сущностей слоя (тип, позиция, здоровье)
  пишется в таблицу `entities_dump` зеркала — смотрите в любом SQLite-клиенте;
- `DP_Storage_live_wipe.txt` — **удаление из мира** по тем же фильтрам.

Примеры: `vehicles` (весь слой), `vehicles CivilianSedan*` (семейство типов),
`loot Ammo_* @ 7500,8500,100` (только вокруг точки — чистка конкретной базы).
Слои: `vehicles|zombies|animals|loot|stashes|buildings`. Проверено на проде:
дамп 62 машин по типам; выборочный вайп `CivilianSedan*` — удалены только они.

Триггеры без правки кода (проверяются каждые 30 с):

- `$profile:DP_Storage_wipe.txt` — UID на строку, вайп персонажей (живьём);
- `$profile:DP_Storage_layer_wipe.txt` — слой на строку, вайп при следующем старте;
- `$profile:DP_Storage_live_wipe.txt` — слой на строку, живой вайп (vehicles/zombies/animals);
- логи: `profiles\DP_Storage_layer_wipe.log`, `profiles\dp_storage_mirror.log`.

Проверено на DayZ 1.30 (retail `DayZServer_x64.exe`):

- параллельный доступ к SQLite из плагина при работающем сервере — без конфликтов;
- вайп оффлайн-игрока: `OK deleted=1`, база цела;
- вайп онлайн-игрока: запись удаляется «под носом» движка, logout-сейв её НЕ
  воскрешает (похоже, сейв идёт UPDATE по Id) — следующий вход = свежий персонаж;
- у вайпнутого игрока клиент при следующем входе может попросить рестарт игры
  (рассинхрон сессии) — ожидаемое поведение.

Триггер без рестарта: флаг-файл `$profile:DP_Storage_wipe.txt` (по одному UID
на строку), проверяется при старте миссии и каждые 30 с.

## Сборка

Тулчейн: VS Build Tools 2022 (C++ workload), LLVM (clang-cl 17+), CMake 3.30+,
Ninja, Mikero MakePbo. Одной командой (сам находит окружение):

```powershell
powershell -File deploy.ps1                                  # деплой в @server
powershell -File deploy.ps1 -Game "C:\..." -ModDir "@server" # другой сервер
```

Ядро graft ставится один раз: `graft install <каталог сервера>` (hid.dll рядом
с exe). Серверная сторона — без ограничений; клиентская часть graft не
используется (несовместима с BattlEye).

## Структура

```
src/plugin.cpp                    C++-плагин (winsqlite3.dll динамически)

deploy.ps1                        сборка + упаковка + деплой
CMakeLists.txt / CMakePresets    graft_import/graft_plugin (TAG v0.4.0)
```
